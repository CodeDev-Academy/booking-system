## 2. Code Review Rubric & Audit Criteria

### A. Frontend Audit Criteria (`frontend/`)
1. **Strict Separation of Concerns (Logic vs Design)**:
   - Does any JSX component make direct `fetch()` or API calls? (FAIL if yes — must use `stores/` or `hooks/`).
   - Does any JSX component contain business math or raw timer calculations? (FAIL if yes).
2. **TasteSkill Design System Compliance (`tasteskill.dev`)**:
   - Palette check: Canvas `#0f0f0f`, elevated cards `#121212` / `#141414`, hairlines `#1f1f1f` / `#2b2b2b`, warm ember gradient `linear-gradient(90deg, #ffb547, #ff6b3d 50%, #ff4f79)`.
   - Typography check: Are timers, dates, and counts styled with `font-variant-numeric: tabular-nums`?
   - Zero Slop: No generic centered cards, no clunky grey shadows, no raw unstyled defaults.
3. **Anti-Overflow & Responsive Guard**:
   - Are flex children protected with `min-width: 0` to prevent text blowout?
   - Is `overflow-x: hidden` enforced on root viewports?
   - Does the navigation rail cleanly collapse to 64px on tablet/laptop viewports (<1024px)?
4. **Console & Build Health**: Zero console errors, zero syntax warnings, clean bundle build.

### B. Backend Audit Criteria (`backend/`)
1. **Zero Double-Booking Concurrency Safety**:
   - Are temporary holds and appointment creations wrapped in `transaction.atomic()` with `select_for_update()`?
   - Is the race condition between manual calendar clicks and online bot selections handled with a clean `409 Conflict` (Risk R-12)?
2. **Dynamic Settings & Zero Hardcoding**:
   - Are durations, buffers, shift hours, and expiry windows dynamically read from `ClinicSetting` and `Service` models instead of hardcoded numbers?
3. **Authentication & Security Compliance**:
   - Are JWT tokens transmitted via `HttpOnly Secure SameSite` cookies?
   - Does setting `is_active = False` immediately eject the user session on the next API call?
   - Is the 4-digit workstation Quick-PIN hashed with salted PBKDF2 and protected by a 3-strike 60-second cooldown rate limit?
4. **Data Privacy & Medical Audit Integrity**:
   - Are medical diagnoses hidden from public/SSE streams (HIPAA/NDPR)?
   - Are patient phone numbers masked in server logs (`+234 801 **** 5678`)?
   - Are cancellations handled as soft-deletes with reasons and immutable records in `AuditLog`?

## 3. How to Report Audit Findings
For every task review, produce a structured markdown report:
1. **Executive Verdict**: `PASSED` / `CHANGES REQUIRED` / `FAILED`.
2. **Compliance Checklist**: Bulleted verification against the rubric above.
3. **Identified Issues / Code Smells**: Specific file paths, line numbers, and actionable remediation steps.
4. **Sign-Off Status in `TEST.md`**: Update corresponding test items (e.g. `T-401`, `T-101`) to `[x]` upon passing.
